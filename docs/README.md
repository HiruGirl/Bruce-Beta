# Bruce Light — CYD-2432S028 web flasher

A small, dependency-minimal flashing page meant to be served from GitHub Pages
on `HiruGirl/Bruce-Beta`. It flashes a merged esptool image to a classic
**CYD-2432S028** (2.8" SPI-touch CYD, 240x320) over Web Serial.

The firmware itself is **not hand-generated by this page** — you build it from
this repo. See "Building the light image" below.

## Building the light image (CYD-2432S028-JSLITE)

The tree contains a trimmed variant of the full Bruce source tree
(`firmware/`). Build exactly the JS-Lite env:

```bash
cd firmware
../.venv/bin/pio run -e CYD-2432S028-JSLITE
```

A successful build produces:

- `firmware/Bruce-CYD-2432S028-JSLITE.bin`  — the merged bootloader + partition table + app image

The resulting bin is ~1–3 MB, so copy it next to `docs/index.html` as:

```
docs/firmware/Bruce-CYD-2432S028-JSLITE.bin
```

and re-publish the Pages site (Actions/manual push of the `docs/` folder).
`docs/assets/config.js` defaults to loading that file from the same origin.

> Sanity check first: `python3 -c "import pathlib;print(pathlib.Path('firmware/Bruce-CYD-2432S028-JSLITE.bin').stat().st_size)"` should be in the 1 MB – 3.5 MB range.

## What this build keeps

WiFi (AP + station), BLE, the JS interpreter (mquickjs) with storage/display/BLE/WiFi helpers,
the always-on Clock startup app, and the "Others" menu (QR codes, Megalodon).

What it drops (from the trimmed upstream) — hidden from the main menu and everything
tied to those features: RF/SubGHz, NRF24, IR, RFID, GPS, LoRa, FM, Ethernet/ARP scan,
SDR, sniffers, DoS/evil-twin attack menus (listen TCP/Client TCP/SOCKS4/Telnet/SSH/NetCut/
Responder/Scan Hosts/Channel Analyzer/Jam Detect/WiFite), BadUSB menu/iButton, Microphone
and HID-mode submenus. The JS interpreter still compiles the BadUSB natives (it shares the
BLE Keyboard stack), but USB HID is not wired on this board.

## Pushing and publishing

```bash
git push origin <your-branch>   # then open the PR (or merge into main)
```

Publishing is automatic on every push to `main`:
`.github/workflows/static.yml` (Deploy static content to Pages) builds a static
artifact from `docs/` and deploys it. Remove the jekyll workflow (we keep only
the static one). The site is live at `https://hirugirl.github.io/Bruce-Beta/`.

## Flasher details

- esptool-js `0.7.1` (vendored at `assets/bundle.js`), vanilla Web Serial
- Merged image format: bootloader @ 0x1000, partition table @ 0x8000, app @ 0x10000
- Flash: `eraseAll=true`, `flashMode=dio`, `flashFreq=80m`, `flashSize=4MB`
- The `firmwareUrl` in `assets/config.js` may also point at any HTTPS-hosted `.bin`
  (e.g. a GitHub release asset) — the flasher will fetch it from the browser.
- Web Serial must be available (Chrome/Edge on desktop; not Safari).

## Why the light build is not in git — actually it is

The built bin IS committed under `docs/firmware/` (build artifacts in the build
tree are ignored, but the published one is not). Once it exists on `main`, the
Pages deployment serves it and the flasher fetches it same-origin. (You can keep
it out of git with `git rm -r --cached docs/firmware` if you prefer to host the
bin elsewhere; the flasher fetches whatever `FIRMWARE_URL` in
`docs/assets/config.js` points at.)
